Access isn’t coverage.

  • Bluesky: official public AppView profile and up to 100 recent authored, non-reply posts.
  • Mastodon: the configured instance’s official API; profile and up to 40 recent original statuses.
  • X: your server-local archive, not an X API connection. Counts retain the archive file’s timestamp.
  • Typefully: a successful, explicitly configured official API request verifies access only. No analytics scope or metrics are assumed.

Follower history begins when you start collecting. The server does not backfill invented daily counters. Re-run sync to append observations; there is no background scheduler.

One file to preview. A private server to go live.

  1. Save this HTML as rooms-os.html in a new folder.
  2. Download the server and schema below. Run the SQL once in your Neon SQL editor.
  3. Install Node 20+ and the PostgreSQL client: npm install pg.
  4. Set environment variables in your server process. Never paste secrets into this page.
  5. Run node rooms-server.mjs, open http://127.0.0.1:8787, and authenticate.
  6. Use Connection → “Fetch → store → read back.” Review every source result, including failures.

The server binds to loopback only. Do not expose it over plain HTTP. For remote use, put it behind a private HTTPS reverse proxy/VPN with access control. HTTP Basic authentication is transport-safe only over HTTPS or a trusted loopback connection.

X import accepts standard tweets.js, its raw JSON array, or normalized JSON records with id, publishedAt, text and optional numeric metrics. Missing metrics stay null. Up to 10,000 records are imported per run. Do not upload private archives to third-party tools.

Use a dedicated Neon database role with access only to the rooms schema. This application stores post text and counters; apply your own retention and backup policy. No browser cache or localStorage is used for private data.

One schema. Append-only metric observations.

Source records are committed together with a run marker. A later request counts the stored observations independently. Account counters and post metrics retain their own observation times.
